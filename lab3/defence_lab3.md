### 1. **Определение процедуры**

вмиыПроцедура в языке Ассемблера — это именованный блок кода, предназначенный для многократного вызова. Она определяется парой директив:

```asm
имя_процедуры PROC  
    ; тело процедуры  
    RET [n]  
имя_процедуры ENDP  
```

- `PROC` задаёт начало процедуры и связывает её с меткой.
- `ENDP` — обязательный конец, имя должно совпадать с именем в `PROC`.
- Обязательной завершающей командой является `RET`, которая обеспечивает возврат в точку вызова.
- Опциональный параметр `n` в `RET n` используется в соглашениях вроде `stdcall` для автоматической очистки стека.

---

### 2. **Команда вызова процедуры CALL**

Команда `CALL имя_процедуры` выполняет два действия:

1. Сохраняет в стек **32-битный адрес возврата** — адрес следующей после `CALL` инструкции.
2. Загружает в регистр-указатель команд `EIP` адрес начала процедуры (значение метки).

Это обеспечивает передачу управления процедуре и последующий корректный возврат.
Формат:

```asm
CALL метка    ; прямой вызов
CALL регистр  ; косвенный вызов
```

---

### 3. **Команда возврата из процедуры**

Команда `RET` завершает выполнение процедуры и возвращает управление вызывающей программе. Она:

- извлекает из стека сохранённый адрес возврата,
- загружает его в `EIP`.

Если используется `RET n`, то после извлечения адреса из стека дополнительно удаляется `n` байт — это необходимо в соглашениях типа `stdcall`, где очистка стека от аргументов лежит на вызываемой процедуре.

---

### 4. **Косвенный вызов процедуры**

Косвенный вызов происходит не по имени, а через **указатель на процедуру**, хранящийся в регистре или памяти.

Пример:

```asm
mov eax, OFFSET my_proc  
call eax  
```

Это позволяет реализовывать динамическое связывание, таблицы функций, callback-механизмы.

---

### 5. **Основы взаимодействия языков C++ и Ассемблера**

В среде Microsoft Visual Studio возможна **многоязыковая разработка**: модули на C++ и Ассемблере компилируются и линкуются в единый исполняемый файл.

**Ключевые требования:**

- **Согласованное соглашение о вызовах** (`cdecl`, `stdcall`, `fastcall`).
- **Совместимое управление регистрами**: процедура не должна портить значения callee-saved регистров (`EBX`, `ESI`, `EDI`, `EBP`) без их сохранения.
- **Корректное декорирование имён**: компилятор C++ добавляет префиксы/суффиксы к именам (например, `_имя` для `cdecl`, `_имя@N` для `stdcall`).

Чтобы избежать name mangling, в C++ используется `extern "C"`.

---

### 6. **Использование глобальных данных для передачи данных процедуре на языке Ассемблера**

Глобальные переменные, определённые в C++-модуле с `extern "C"`, доступны из ассемблерного модуля через директиву `EXTERN`.

Пример из методички:

```cpp
// C++
extern "C" int VAL = 0;
```

```asm
; ASM
EXTERN _VAL: DWORD
...
mov _VAL, 4
```

> **Важно:** компилятор C++ добавляет подчёркивание к глобальным именам → в ассемблере используется `_VAL`, а не `VAL`.

Этот способ прост, но **не рекомендуется** для сложных программ из-за побочных эффектов и проблем с многопоточностью.

---

### 7. **Использование аргументов функции для передачи данных процедуре на языке Ассемблера**

Аргументы передаются через **стек** (в `cdecl`, `stdcall`) или **регистры** (`fastcall`).

#### В соглашении `cdecl` (по умолчанию в C++):

- Аргументы помещаются в стек **справа налево**.
- Вызывающая функция **очищает стек** после вызова (`add esp, N`).
- Доступ к аргументам в процедуре осуществляется через `EBP`:
  - `[ebp+8]` — первый аргумент,
  - `[ebp+12]` — второй и т.д.

**Стандартная пролог-эпилог последовательность:**

```asm
push ebp
mov ebp, esp    ; теперь EBP — база фрейма
; работа с [ebp+8], [ebp+12]...
mov esp, ebp
pop ebp
ret
```

---

### 8. **Возвращение значений из процедуры на языке Ассемблера**

Возвращаемое значение передаётся через **регистры**, в зависимости от размера:

- 8 бит → `AL`,
- 16 бит → `AX`,
- 32 бита → `EAX`,
- 64 бита → `EDX:EAX`.

Если функция на C++ объявлена как `int func(...)`, то ассемблерная процедура **должна** поместить результат в `EAX`.

Пример:

```cpp
extern "C" int add(int a, int b);
```

```asm
mov eax, [ebp+8]
add eax, [ebp+12]
ret
```

---

### 9. **Вызов функций на языке C++ из процедур на языке Ассемблера**

Для вызова C++-функции из ассемблера:

1. Объявить её через `EXTERN` с учётом декорирования:
   ```asm
   EXTERN _CFUNC: PROC   ; для cdecl
   ```
2. Поместить аргументы в стек **в обратном порядке**.
3. Вызвать через `CALL`.
4. **Очистить стек** (в `cdecl` — вызывающая сторона, то есть ассемблерная процедура):
   ```asm
   push 5
   push 3
   call _CFUNC
   add esp, 8   ; 2 аргумента × 4 байта = 8
   ```

---

### 10. **Использование локальных данных**

Локальные данные создаются в **стековом фрейме** процедуры.

Этапы:

1. Сохранить `EBP`: `push ebp; mov ebp, esp`.
2. Выделить место: `sub esp, N` (N — размер локальных данных).
3. Обращаться через `[ebp - смещение]`.

Пример:

```asm
sub esp, 4          ; 4 байта под int
mov DWORD PTR [ebp-4], 100
```

После использования — восстановить стек через `mov esp, ebp; pop ebp`.

---

### 11. **Использование вставок на языке Ассемблера в программе на языке C++**

В MSVC (только x86) поддерживается **встроенный ассемблер** (`__asm`).

Пример:

```cpp
int a = 5, b = 10, result;
__asm {
    mov eax, a
    add eax, b
    mov result, eax
}
```

**Назначение:**

- Оптимизация узких мест,
- Доступ к специфичным инструкциям CPU,
- Образовательные цели.

**Ограничения:**

- Не поддерживается в x64-версии MSVC,
- Нарушает переносимость.

## 📌 Основные соглашения в x86 (32-бит Windows)

В методичке упоминаются три ключевых соглашения: **`cdecl`**, **`stdcall`**, **`fastcall`**. Рассмотрим каждое.

---

### 1. `cdecl` — «C declaration» (по умолчанию в C/C++)

> **Используется:** по умолчанию во всех функциях C/C++, если не указано иное.

#### ✅ Как передаются аргументы?

- Через **стек**.
- **Справа налево** (последний аргумент кладётся первым).

#### 🧹 Кто очищает стек?

- **Вызывающая функция** (caller).

#### 🔚 Как выглядит возврат?

- В `AL` / `AX` / `EAX` — в зависимости от размера.

#### 🏷️ Декорирование имени (name decoration):

- К имени добавляется **одно подчёркивание спереди**:
  `func` → `_func`

#### 💡 Пример вызова на C++:

```cpp
int add(int a, int b) { return a + b; }
// вызов: add(10, 20);
```

Компилятор генерирует:

```asm
push 20        ; второй аргумент
push 10        ; первый аргумент
call _add
add esp, 8     ; ОЧИСТКА СТЕКА (2 × 4 = 8) — делает вызывающая сторона!
```

#### 📦 Ассемблерная реализация:

```asm
_add PROC
    push ebp
    mov ebp, esp
    mov eax, [ebp+8]   ; a
    add eax, [ebp+12]  ; b
    pop ebp
    ret                ; просто ret — без очистки!
_add ENDP
```

> ✅ **Плюс:** поддерживает функции с переменным числом аргументов (`printf`, `scanf`), потому что только вызывающая сторона знает, сколько аргументов было передано.

---

### 2. `stdcall` — «standard call» (используется в WinAPI)

> **Используется:** почти во всех функциях Windows API (`MessageBoxA`, `CreateFile`, и т.д.).

#### ✅ Как передаются аргументы?

- Через **стек**.
- **Справа налево** — как в `cdecl`.

#### 🧹 Кто очищает стек?

- **Вызываемая функция** (callee).

#### 🔚 Возврат:

- Тот же: `EAX`.

#### 🏷️ Декорирование имени:

- `_имя@N`, где **N — общее количество байт аргументов** (в десятичной системе).
  Пример: `func(int, int)` → `_func@8`
  `ExitProcess(DWORD)` → `_ExitProcess@4`

#### 💡 Пример на C++:

```cpp
extern "C" void __stdcall copy_block(void* src, void* dst, int len);
```

#### 📦 Ассемблер:

```asm
_copy_block@12 PROC
    push ebp
    mov ebp, esp
    ; ... работа с [ebp+8], [ebp+12], [ebp+16]
    mov esp, ebp
    pop ebp
    ret 12        ; ← ВАЖНО: очищаем 12 байт из стека!
_copy_block@12 ENDP
```

> ❌ **Минус:** не поддерживает переменное число аргументов — потому что вызываемая функция должна знать, сколько байт удалять.

---

### 3. `fastcall` — «fast call» (оптимизированная версия)

> **Используется:** когда важна скорость — минимизация работы со стеком.

#### ✅ Как передаются аргументы?

- **Первые два 32-битных аргумента** — через **регистры `ECX` и `EDX`**.
- **Остальные** — через стек (**справа налево**).

#### 🧹 Кто очищает стек?

- **Вызываемая функция**.

#### 🏷️ Декорирование:

- `@имя@N` (обрати внимание: **собачка спереди**, а не подчёркивание!)
  Пример: `func(int a, int b, int c)` → `@func@12`
  (a → ECX, b → EDX, c → стек → 4 байта → итого 12)

#### 💡 Пример:

```cpp
extern "C" int __fastcall calc(int x, int y, int z);
```

Вызов:

```asm
push 100       ; z (третий аргумент → в стек)
mov edx, 20    ; y → EDX
mov ecx, 5     ; x → ECX
call @calc@12
; ← НЕТ add esp,4 — очистка делается внутри!
```

#### 📦 Ассемблер:

```asm
@calc@12 PROC
    ; ECX = x, EDX = y, [esp+4] = z (адрес возврата на [esp])
    mov eax, ecx
    add eax, edx
    add eax, [esp+4]
    ret 4          ; удаляем 4 байта (только z)
@calc@12 ENDP
```

> ⚡ **Плюс:** быстрее — меньше операций со стеком.
> ⚠️ **Минус:** менее переносимо, зависит от компилятора.

---

## 🧠 Почему это так важно при взаимодействии C++ и ассемблера?

Потому что **ошибка в соглашении = катастрофа**:

- Если в `stdcall` забыть `ret 12`, стек **сдвинется**, и следующий `ret` вернётся не туда → **crash**.
- Если в `cdecl` не сделать `add esp, N`, стек **заполнится мусором** → тоже crash.
- Если в ассемблере объявить `_func`, а C++ ожидает `_func@8` — линковщик выдаст **ошибку "undefined reference"**.
